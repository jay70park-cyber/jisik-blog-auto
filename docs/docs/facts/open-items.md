## 고시 `현안` 열은 수집 당시 키워드로 한 번 적히고 끝난다 — 2026-10-22

**증상.** 키워드를 고쳐도 과거 고시는 옛 연결을 들고 있다. 본체
(`collect_hscity`)는 새로 올라온 고시만 태그한다.

**왜 조용히 안 넘어가는가.** `collect_sources.py`:

```python
tagged = name and name in (r.get("현안") or "")
if not (tagged or any(w in title for w in words)):
    continue
```

**`또는`이다.** 옛 태그가 붙어 있으면 키워드를 아무리 좁혀도 그 고시는
글 쓸 재료로 계속 들어온다. 최근진전일은 `update_agenda()`가 새 고시만
보므로 영향이 없지만, **재료는 샌다.** A002 고려대 뉴스 90건과 같은
사고가 다른 문으로 들어오는 구조.

**조치.** `scripts/retag_notices.py` + `.github/workflows/retag.yml`
(일회용, 기본 미리보기). 2026-10-22 적용 완료 — 827건 중 34건 재연결,
점검에서 `연결이 바뀌는 고시 0건` 확인.

| 현안 | 증감 | 뜻 |
| --- | --- | --- |
| 동탄 주택공급 | +17 -3 | 5년치 연표 재료가 생김 (그동안 과거분 0건) |
| 화성 산업단지 조성 | +9 -2 | |
| 동탄 상권 변화 | +2 -0 | 원공고+정정 한 쌍 — **실질 +1** |
| GTX-A | +0 -1 | GTX-C 공고 제거 |

`+`가 많은 것은 오류가 아니라 **현안이 나중에 추가돼** 그 전 고시가
태그될 기회가 없었던 것이다 (A009 추가일 2026-09-17).

**미결 — 자동화할지.** `collect_hscity.main()`이 매 실행마다 누적 전체를
다시 태그하게 하면 근본 해결이다. 827건 × 현안 10개라 비용은 없다시피
하고, `update_agenda()`는 새 고시만 보므로 최근진전일 동작은 안 바뀐다.
단점은 매 실행이 전체 파일을 다시 써서 커밋 차이가 커지는 것.
**지금은 일회용으로 두고 다음 키워드 수정 때 다시 판단한다.**

**가 안의 비용이 드러난 건 1건.** `화성 일반산업단지 개발계획 변경(안)
주민공람`(2026-09-29)은 제목에 산단 이름이 없어 떨어졌다. 주곡·동방·무송
중 하나면 9/29 주민공람 → 10/6 토지수용재결로 이어지는 흐름이라 글감
가치가 있다. **`현안` 열을 손으로 고쳐도 다음 재태깅 때 지워지므로**
(수기 보존 열이 아님) 확인되면 `local_agenda.csv` 메모에 적을 것.
